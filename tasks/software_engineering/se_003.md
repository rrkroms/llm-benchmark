# SE-003 — Safe Refactor Plan

A legacy service has a 400-line function that:

1. parses a request
2. validates business rules
3. reads configuration
4. calls an external API
5. transforms the response
6. writes to a database
7. formats an HTTP response

The function is duplicated in two modules and has weak tests.

## Task
Design a safe refactor that improves maintainability without changing externally observable behavior.

Include:

- proposed module/function boundaries
- dependency injection strategy
- test strategy before and after refactor
- compatibility strategy
- rollback plan
- handling of external API failures
- handling of database failures
- performance considerations
- how to prove behavior did not change

Do not invent framework-specific details that are not given.
